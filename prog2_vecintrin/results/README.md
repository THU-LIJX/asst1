# Problem 2：向量宽度与模拟 SIMD 利用率

本实验使用当前工作区的 clampedExpVector 实现，完成 README 要求的 N=10000、VECTOR_WIDTH=2、4、8、16 扫描。每种宽度运行两次，指令数和通道计数完全一致；全部正式运行通过必做指数计算及加分求和的结果校验。

## 实验方法

- 实验开始：2026-10-14T15:24:42.678432+08:00。平台：macOS-26.5.2-arm64-arm-64bit-Mach-O，架构：arm64。
- 机器：Apple M3，8 个物理核心、8 个逻辑 CPU，16 GiB 内存。
- 编译器：Apple clang version 16.0.0 (clang-1600.0.26.4)。
- 编译参数：`-std=c++11`；头文件参数：`-I../common`。保持原 Makefile 默认配置，没有增加优化参数。
- 不修改原源码。在临时副本中调整 VECTOR_WIDTH，每种宽度强制重新编译所有编译单元，独立进程运行 `./myexp -s 10000`；完成后清理副本。
- 保留原输入生成方式：程序未调用 srand，各次独立进程从同一默认 rand 序列开始。初始化按元素依次调用 rand；尽管缓冲区长度随宽度变化，前 10000 个元素及指数相同。该输入序列依赖本机 C 运行库，不保证跨平台相同。
- 每种宽度额外检查 N=1、3、5、W−1、W、W+1，去除重复值；验证输出及额外保护区。求和只在 N 能被 W 整除时执行。
- 利用率从精确整数计数重新计算，并核对程序只保留一位小数的输出。这些计数是模拟器的确定性统计，不进行墙钟测速，不取性能中位数。

| 2 | 173032 | 296939 | 346064 | 85.8046% | 85.8% | 通过 | 通过 |
| 4 | 99564 | 323043 | 398256 | 81.1144% | 81.1% | 通过 | 通过 |
| 8 | 54040 | 340091 | 432320 | 78.6665% | 78.7% | 通过 | 通过 |

## 利用率趋势与解释

**实测结果：**利用率随向量宽度增大而逐步下降；从宽度 2 的 85.8046% 变为宽度 16 的 77.4682%。

每个元素的指数来自 rand() % 10，取值为 0–9。向量组内不同元素需要不同次数的乘法；当前循环在所有非零计数通道完成后才退出。已经完成的通道会被掩码关闭，但整个组仍要等待尚未完成的通道。向量越宽，一个组内包含较大指数并形成不同完成时间的机会越多，因此循环中的通道空闲可以解释利用率下降的趋势。这是结合当前实现与输入的解释，并不是任意程序的利用率都会随宽度下降。

N=10000 可被四种宽度整除，正式实验没有不完整尾块，不能把趋势归因于最后一组未填满。源码中的索引更新、比较和其他向量操作也参与统计。logger 按每条已记录指令的掩码累计通道数，cntbits 等操作记录为全通道启用，init_ones 本身不记录指令；整体利用率包含这些操作，不能只用乘法次数推导它。

利用率与总指令数是不同指标：较低利用率不等于总模拟指令更多。按照 README 的简化模型，每条模拟向量指令视为一个周期，可以比较表中的总向量指令数。这些统计不是 M3 原生 SIMD 的硬件利用率，也不能直接作为真实 CPU 加速比。
