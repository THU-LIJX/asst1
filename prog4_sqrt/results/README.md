# Problem 4：迭代平方根的 SIMD 与多核实验

本目录完成前三个必做问题；不包含手写向量指令的加分题。

## 方法与统计口径

实验时间：2026-10-15T11:11:47.598115+08:00 至 2026-10-15T11:20:12.451330+08:00。机器为 Apple M3，4 个性能核心、4 个能效核心，8 个物理核心及逻辑 CPU，16 GiB 内存。本轮没有固定核心、改变 QoS 或系统设置；实验开始及结束均接通电源，开始时低电量模式关闭；完整查询见环境记录。

- 每种输入 N=20,000,000，独立启动 10 次。每次按串行、单核 ISPC、task ISPC 的固定顺序，各运行 3 次，分别取最短时间；表中报告跨启动的中位数。加速比先在每次启动内计算，再汇总中位数和四分位数。
- 正式配置每轮使用种子 7 打乱，逐个运行；输入 rand 种子为 1。每种配置先预热一次，预热不计入统计。未同时运行其他性能测试。
- SIMD 加速比 = T串行 / T单核ISPC；总加速比 = T串行 / TtaskISPC；多核额外收益 = T单核ISPC / TtaskISPC。三个中位数因独立统计不要求严格相乘。
- 使用原来的牛顿迭代公式、初值 1、阈值 1e-5、编译优化及 GCD 任务运行时。不在内核中加入计数或诊断。每次计时前填充 NaN，计时后检查所有元素有限，绝对误差 ≤ 1e-4 且相对误差 ≤ 1e-5；初始化和校验均不计时。
- C++：`clang++ -O3 -std=c++11 -Wall`；ISPC：`ispc -O3 --target=neon-i32x8 --arch=aarch64 --pic`。未关闭 FMA。Clang 与 ISPC 的指令生成、浮点收缩及循环控制可能不同，不能将时间比完全视为通道利用率。
- `neon-i32x8` 的 programCount 为 8，即逻辑 gang 宽度 8；M3 NEON 原生向量宽度为 128 bit，一次容纳 4 个 float。题目将此目标简称为“8-wide 指令”不够准确，8×不是 M3 的严格加速上限，4×同样不是这一时间比的严格上限：比较的是两个编译器生成的完整循环，指令调度、控制开销和浮点收缩均可能不同。
- 默认 2000 万输入沿用 64 个 task，每块 312500 个元素。只修复小规模输入的零 span 和非整除尾块问题，默认规模的划分未变。任务数不等于核心数，也没有实测每个 task 落在哪类核心。

工具版本：`Apple clang version 16.0.0 (clang-1600.0.26.4)`；`Intel(r) Implicit SPMD Program Compiler (Intel(r) ISPC), 1.31.0 (build commit  @ 20260625, LLVM 23.1.3)`；Python `3.13.1`。

## 1. 原始随机输入

输入保留原公式 `0.001f + 2.998f * rand() / RAND_MAX`，独立进程使用相同随机序列。

原始输入的 SIMD 加速为 **4.42×**，task 版本相对串行为 **27.14×**；从单核 ISPC 切换到 tasks 的额外收益为 **6.17×**。后者才是这里的多核加速比。

## 2. 提高相对加速比的输入

本轮统一输入中，单核 SIMD 加速比最高的是 **统一 1e-30**：SIMD **5.50×**，总加速 **33.81×**，多核额外收益 **6.15×**。总加速最高的统一配置为 统一 1e-30，达到 33.81×。

让所有元素取同一个较难收敛的正数，各 lane 的终止条件一致，消除迭代次数差异导致的掩码空转。较多迭代也能摊薄加载、写回和循环外围开销。`1e-30f` 在题目允许的 (0, 3) 内，是正常浮点数，但超出了原随机生成器约 [0.001, 2.999] 的范围；因此同时保留接近 3 的统一输入作为另一组对照。`2.99999976f` 是小于 3 的最大 float，不能写成 3：初值 1 在 x=3 时下一步成为 0，无法收敛。

相对原始随机输入，所选统一输入的 SIMD 比值为 5.50× 对 4.42×，多核额外收益为 6.15× 对 6.17×。本轮 SIMD 加速比提高约 24.5%；多核额外收益基本持平，四分位范围重叠，未见明显改善，也不将这点微小差异视为统计显著的退步。消除 gang 内分歧主要改善单核向量执行，并不会增加可用核心。多核比值还受任务开销、P/E 核算力差异、调度、频率和内存访问影响。

你的 `2.0f + 0.1f * rand() / RAND_MAX` 保留为 `--input user`。它减少总迭代次数，可能降低绝对耗时，但不能据此推出相对串行的加速比更高。输入一致性也可能提高串行分支的可预测性；因此消除分歧并不保证每一种统一输入都比原随机输入获得更高的相对加速比，统一 0.1 就是一个反例。表中的“最优”仅指本次所测候选及机器状态，不声称穷举所有 float 后的数学全局最大值。

## 3. 降低单核 ISPC 相对性能的输入

正式分歧配置中最低 SIMD 加速比来自 **每组 0.1 + 七个 1**：SIMD **0.44×**，即单核 ISPC 耗时约为串行的 **2.26 倍**；task 总加速为 **2.27×**。

按逻辑 gang 宽度 8 构造：`values[i] = (i % 8 == 0 ? slow : 1.0f)`。`x=1` 在初值 1 时立即满足精度条件；其余每组仅一个 lane 需要反复迭代。串行能直接跳过七个简单元素，ISPC 的 gang 必须等最慢 lane，循环中最多只有约 1/8 的逻辑 lane 有效。这只是迭代主体的有效 lane 比例，不是整段程序或物理执行单元的实测利用率。

控制慢值同为 0.1 时，统一输入 SIMD 为 2.95×，分歧输入为 0.44×。这一对照支持分歧降低向量效率的解释。mask、终止判断以及代码生成也有成本，所以实际时间比不会精确等于统一版本的 1/8。tasks 仍可让不同 gang 并行，但不会消除 gang 内的掩码空转。绝对耗时更短与相对加速比更低可以同时发生。

任务版本的块起点有时不按 8 对齐；上述周期输入依然让每个完整连续八元素包含一个慢值，块尾仅有少量部分 gang。没有通过调整划分或任务数量来改善实验结果。候选筛选不是全输入空间搜索；“最低”同样仅限本轮正式候选。

## 复现与记录

在仓库根目录执行：

```sh
make -B -C prog4_sqrt
./prog4_sqrt/sqrt --input random
./prog4_sqrt/sqrt --input user
./prog4_sqrt/sqrt --input uniform --value 1e-30
./prog4_sqrt/sqrt --input divergent --value 0.1
.venv/bin/python prog4_sqrt/benchmark.py --output-dir /tmp/sqrt-repeat
```

- [raw.csv](raw.csv)：每次启动的三个最短耗时、重算比值及日志路径。
- [summary.csv](summary.csv)：每配置中位数及第 25、75 百分位。
- [experiments.json](experiments.json)：时间、配置、工具、编译命令、源码标识与校验记录。
- [logs/](logs/)：构建、小规模/无效参数检查、预热和全部正式输出。
- [pilot/](pilot/)：正式实验前的小规模候选筛选；只用于选取配置，不混入正式统计。

筛选每个配置仅运行一次、内部仍取三次最短值；它适合发现候选，不能替代完整规模的重复测量。正式配置固定为原始输入、你的输入、三组统一输入和两组分歧输入，重复实验使用相同集合，便于复现。

本轮没有测量各 lane 的实际指令数、各核心频率或调度轨迹；关于掩码行为的解释来自输入结构和源码，关于异构核心及频率的影响属于可能原因。
